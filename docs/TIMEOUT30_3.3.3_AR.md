# المطوف الذكي 3.3.3 — اتصال Eye ومهلة 30 ثانية لكل مرحلة

الإصدار المستهدف `3.3.3-timeout30`، رقم بناء19. يعالج اختيار مسار الإنترنت عند توصيل Eye، ويمنح الخادم رفع الصورة30ثانية وانتظار إجابة المساعد30ثانية، سواء للتعرف على الصورة أو لسؤال الوكيل. هذه مهل منفصلة وليست وعداً بأن الطلب كله ينتهي خلال30ثانية.

أظهر سجل المستخدم ست مهلات اتصال محلية بعد نحو10ثوانٍ، في مرحلة `CONNECT` مع صفر بايت مرفوع، بينما استمرت صورة Eye بنحو13إطاراً/ثانية وعملت الحساسات. المشكلة المرصودة في هذا السجل سبقت رفع الصورة ووصولها إلى المساعد؛ وهي مختلفة عن اختبار الرفع البطيء السابق. لا يحدد السجل وحده أي شبكة اختارها Android. التعديل الجاري يختار مسار إنترنت مؤهلاً ويتجنب شبكة ملحق غير صالحة للإنترنت مع احترام VPN؛ لا يكفي تمديد مهلة الرفع وحده لمعالجة فشل الاتصال.

نجحت اختبارات الخادم70/70، ومنها رفع16ثانية لكلا المسارين وانتهاء الرفع غير المكتمل عند30ثانية. البناء النهائي لاختيار شبكة الإنترنت وفحص توافق المهل والنشر وتجربة الرفع البطيء والتغليف قيد الانتظار. لا تُنسب نتائج إصدار سابق إلى APK هذا الإصدار.
<!-- release-verification:end -->

قد ينتظر الطلب في الطابور حتى8ثوانٍ؛ مجموع المراحل الأقصى68ثانية. عميل التطبيق ووسيط الخادم يحتاجان75ثانية لهذا المسار، بينما مهلة استقبال طلب HTTP في Node تبلغ60ثانية ومهلة الرؤوس15ثانية. حد الصورة400KiB وحد الجسم600KiB وحدود الطلبات والطابور والمزود كما هي. لا توجد إعادة محاولة خفية من الخادم ولا نتيجة بديلة مصطنعة.

إذا انتهى وقت الرفع قبل اكتمال الصورة، يرجع `VISION_UPLOAD_TIMEOUT`؛ وإذا انتهى انتظار المزود يرجع `VISION_TIMEOUT`. يظل التطبيق يحترم وقت إعادة المحاولة المعلن. رفع المهل يتيح وقتاً أطول للشبكة والمزود، ولا يثبت وحده إصلاح سبب تكرار المحاولة على نظارة فعلية.

فحص هذا الإصدار المتوقع يربط إعدادات المهل الثابتة ببصمة APK الناتج، مع الاختبارات وLint. ليس ذلك فحص واجهة جديداً على المحاكي. تختبر تجربة الخادم صورة عامة مصرحاً بها، ولا تثبت شبكة المستخدم أو جودة التعرف والصوت على Fold7 وXREAL Eye. يبقى الاسم الظاهر «المساعد الذكي» من3.3.2.
